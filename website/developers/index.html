Developer guide

A concise map of the current iOS project, its local reference backend, and the capability boundaries that future changes must preserve.

On this pageRequirementsBuild and testSource structureProduct truthChange checklistArchitecture
Internal documentation: this page describes the repository’s unreleased human-validation candidate. It is not a public API promise, partner integration guide, or production-readiness claim.

Requirements

  • Xcode with the iOS 17 or newer simulator runtime
  • The SmartCart.xcodeproj project and SmartCart scheme
  • Node.js 20 or newer only when running the optional local reference backend
  • No website build dependency: this Milestone 8 package is plain static HTML, CSS, and JavaScript

Build and test the iOS app

xcodebuild test \
  -project SmartCart.xcodeproj \
  -scheme SmartCart \
  -destination 'platform=iOS Simulator,name=iPhone 17'

The repository test suite covers parsing, package conversion, preference constraints, matching and fallback behavior, product encoding and staleness, persistence and migration, manifest behavior, replacements, and handoff capability boundaries.

Test the optional local backend

cd backend
npm test

The zero-dependency Node.js service uses only local, in-memory demo state. Its mock sessions, OAuth scaffold, manifests, analytics ingestion, and affiliate abstraction are test foundations—not hosted production capabilities.

Non-negotiable product truth

  • The current DemoWalmartCatalogService uses seeded demo product records.
  • Live price refresh is an unsupported capability.
  • Barcode lookup uses a small bundled offline demo cache rather than a live product database.
  • Search fallbacks are not exact product links and have no SmartCart price.
  • The guided handoff does not transfer a cart, reserve pickup, or submit payment.
  • Local diagnostic events are not hosted production analytics.
  • Generic delivery-provider, multi-stop, creator, connector, OAuth, and affiliate surfaces remain experimental or local-only.
  • Registry profiles and retailer API or partner-feed enum cases express potential shapes; they are not evidence that production integrations exist.

Change checklist

  1. Add or update focused tests before widening a capability claim.
  2. Keep exact-product and search-fallback labels distinct.
  3. Preserve source, observation time, price type, and availability context.
  4. Update README, changelog, website FAQ, privacy draft, terms draft, and affiliate disclosure when data flow or monetization changes.
  5. Re-run the iOS suite and python3 website/validate.py.
  6. Have humans verify legal, domain, email, distribution, partner, and production-hosting facts.
