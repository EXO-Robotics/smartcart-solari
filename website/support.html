Troubleshoot the current build

These steps cover the unreleased validation candidate. A verified human support channel must be added before this site is published.

Recipe import did not work

  1. For a photo, use a clear, well-lit image with the ingredient list fully visible.
  2. Review recognized text before continuing; image recognition can misread quantities or units.
  3. For a recipe page, confirm the page is publicly reachable and exposes supported schema.org recipe metadata.
  4. If the page is blocked or unsupported, paste the ingredient text instead.

A product match looks wrong

  1. Check the ingredient name, quantity, unit, dietary rules, organic policy, and fulfillment mode.
  2. Look for the source label. “Retailer search” is a fallback, not an exact product match.
  3. Verify package size, labels, allergens, availability, and price at the retailer before adding anything.
  4. Use the in-app replacement flow when a different seeded record is more appropriate.

A price or store detail is incorrect

This is expected in the current demo. Product prices, availability, store names, distances, addresses, and pickup windows are seeded or prototype data—not a live retailer feed. The beta cannot refresh them.

The app did not create a cart or reserve pickup

That behavior is outside the current candidate. SmartCart saves a manifest and guides the shopper through exact links or labeled searches. Cart creation, pickup reservation, substitution submission, payment, and checkout happen only at the retailer and are not automated by SmartCart.

A barcode is not recognized

Camera scanning requires a supported physical iPhone; use manual UPC entry in the Simulator. The lookup is a small offline demo cache, not a live product database, so unknown codes are expected and remain unmatched for manual review.

Local state appears damaged

The app uses versioned JSON persistence and can quarantine corrupt state. Before resetting a test build, record the visible error and preserve reproducible steps. Beta testers should use the approved private-beta reporting channel once one is provided.

Include this in a beta report

  • App version and iOS version
  • Import method used
  • Steps immediately before the issue
  • What you expected and what happened
  • Whether the issue repeats after relaunch
  • A screenshot with personal information removed
Privacy reminder: do not include full recipes you do not have permission to share, retailer account details, payment data, precise location, or other sensitive information in a support report.
